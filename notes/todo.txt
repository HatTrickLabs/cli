  Rewrote cursor handling around absolute position + BufferWidth (row = pos/width, col = pos%width) using only
  CUU/CUD/CHA/ED escapes instead of Console.CursorLeft/SetCursorPosition, plus a growable List<char> buffer
  (no more Console.BufferWidth-1 cap). Handles the DECAWM deferred-autowrap quirk explicitly (_pendingWrap).
  Perf follow-up: pasting mid-buffer (e.g. Home then paste) was O(pasted length * existing tail length) -
  every inserted char repainted the whole tail. HandleInsertBurst now batches a run of characters that
  arrive already-queued (Console.KeyAvailable) into one InsertRange + one repaint instead of one per char.
  Added a 64K (65536 char) MaxLength cap - not for the terminal-row limitation (that's fully gone), just
  a sane memory/render-cost ceiling against a pathologically large paste. Throws InvalidOperationException.
  Resize mid-read: Console.BufferWidth is still cached once at read start (re-checking it per key turned
  out to be effectively free - a Console.BufferWidth read is microseconds, dwarfed by any human typing
  interval), but HasResized() now compares live vs cached width on every key (outer loop + inside
  HandleInsertBurst) and abandons the read - returns null exactly like Escape, no exception, no attempted
  cleanup render (which would itself use the stale width and risk making things worse). Content integrity
  was never actually at risk from a resize (the buffer/position bookkeeping never depends on _width - only
  the escape-sequence rendering does), so this is a "stop showing the user a broken screen" fix, not a
